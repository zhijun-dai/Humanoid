# 曝光档位实测：现场步骤

## 为什么做这个

机器人走路时相机剧烈摆动，画面严重运动模糊，**赛道线被"洗灰"**——线的谷底灰阶从清晰帧的
约 15 抬到模糊帧的约 79（对比度 130 → 76）。

实测证据（四段机载视频）：

| 帧清晰度 | 有中线率 | conf 中位 |
|---|---|---|
| 模糊帧（lv 10~40，走路中） | 0~26% | 0.070 |
| **清晰帧（lv ≥150）** | **79~100%** | **0.72~0.99** |

**只有 10~33% 的帧是清晰的。** 算法本身没问题，就是模糊把线糊没了。

模糊长度 = 焦距 × 角速度 × **曝光时间**。缩短曝光能同时冻结平移和转动，是对症的手段。
但缩短曝光会掉进光量、相机会抬增益、噪声上升，可能反而让二值化更差——
**所以缩到哪一档必须实拍定，不能靠推算。**

## 关键认识：换场地也成立

> **曝光时间管的是「钉住模糊长度」，跟光线无关**（模糊只跟速度和曝光时间有关）。
> **亮度应该由增益去补，不该靠拖长曝光。**
>
> 所以这里测出来的不是"学校场地专用值"，而是**曝光上限**。到比赛场地光线不同，
> 让增益自动补，**不要回退成更长曝光**——那样模糊会跟着回来。

## 前置

- 相机装到机器人上，**用平时跑的安装姿态**
- 相机 USB 插到笔记本
- 笔记本上能跑仓库的 python（Windows 上用 `.venv\Scripts\python.exe`）

## 现场步骤（机器人实际行走约 40 秒，全程 5~10 分钟）

**1. 机器人摆到一段直线赛道的起点。**

**2. 开录（在 Jetson 上跑）：**

```
python3 scripts/record_exposure_sweep.py --out 曝光测试 --seconds 10
```

按提示按回车后开始，**每一档让机器人走同一段直线（约 10 秒）**，四档就是走四遍：

```
auto  →  31ms  →  16ms  →  8ms
```

脚本会自动设分辨率、设格式、关自动曝光、设档位、录制、存盘。
**曝光参数用毫秒**——跨平台有意义的物理量（DSHOW 的档位 -5/-6/-7 就是
31/16/8ms，但两边的曝光控制语义完全不同，脚本内部各转各的）。

> 时间紧可只测两档：加 `--exposures auto,16`
>
> 分辨率默认 1280×720（机器人实际运行的档位）。若机器人跑别的分辨率，
> 加 `--width` `--height` 指定，**两边必须一致**。
>
> **在笔记本上跑**（相机插电脑）时注意 `--index`：笔记本内置相机通常排在前面，
> 默认的 0 会录到内置那颗。脚本会打印 `FOURCC` 和 `画面亮度`——
> **如果显示 YUY2 或画面几乎全黑，就是选错相机了**，换 `--index 1` 再试。

**3. 分析：**

```
python3 scripts/analyze_exposure_sweep.py --dir 曝光测试
```

## 输出怎么读

```
曝光    帧数  分辨率  清晰度lv  画面亮度  线谷底灰阶  线像宽  有中线%  conf中位  conf_p75  平坦区噪声
```

| 指标 | 含义 | 期望方向 |
|---|---|---|
| 清晰度 lv | 帧有多锐 | 越大越好（缩短曝光会变大） |
| 画面亮度 | 整体亮度 | **别低于 70**，否则换暗场地会撑不住 |
| 线谷底灰阶 | 线有多黑 | **越小越好**（模糊会把它抬到 50~90） |
| 线像宽 | 线的像素宽度 | 用于算模糊/线宽比 |
| **有中线% / conf** | **巡线的实际表现** | **越大越好——这是选档的主要依据** |
| 平坦区噪声 | 增益噪声 | 别失控（缩短曝光的代价） |

**判据**：选「有中线% 与 conf 最高、同时画面亮度 ≥70、噪声没失控」的那一档。
相邻两档接近时，取曝光更长的那档（信噪比更好）。

脚本会在最后直接给出推荐档位，并提示画面是否偏暗。

## 判读时注意

- 若 `16ms` / `8ms` 的**有中线% 明显高于 auto**，说明缩短曝光确实把赛道线救回来了 ✓
- 若缩短曝光后有中线% 不升反降，看**平坦区噪声**是不是飙了（增益抬太狠）——
  那说明现场光线不够，需要补光而不是继续压曝光
- **画面亮度低于 70 的档位不能选**，换到更暗的比赛场地会崩
