**尺子分开报三个数**，因为它们对应不同的失败：找框率 / 分类率 / 拒判数，外加混淆矩阵。

```bash
python new_vision/scripts/evaluate_shape_cards.py            # 打分
python new_vision/scripts/evaluate_shape_cards.py --dump DIR # 存 warp + binary
```

### 1.2 根因：`_binary_selective` 把卡框锯碎了

`_binary_selective`（`shape_detector.py`）是**为压 2cm 巡线调的**：
blackhat 核9 + 自适应阈值 + 笔画宽 [1.5,7] + 细长度过滤。代价是 **0.5cm 的卡框被打成锯齿**。

**决定性实测**：31 张里只有 **10 张**的卡框轮廓在 `approxPolyDP(eps=0.02)` 下还能收成
**4 个顶点** —— **而那 10 张恰好就是老管线能过的全部**。

四路候选的实测分布：

| 通道 | 每帧出多少 | 实测评价 |
|---|---|---|
| `_hough_quads` / `_lsd_quads` | 各 256（硬上限） | **对卡全被 `area_max` 杀**，等于废的 |
| `_corner_quads` | 0~27 | 主力，6card 上约 2/3 的赢家 |
| `_cc_quads` | 1~2 | 用 `minAreaRect`（旋转**外接矩形**）拟合透视下的**梯形**，对近卡系统性偏大；且它选的最大 CC 常常不是卡 |
| `_ring_quads(ink)` | 0~2 | **新增**，约 1/3 的赢家 |

### 1.3 修法：卡框是个闭合细环

新增两件东西：

- **`_card_ink(gray)`** —— **原始灰度直接 Otsu**，不做 blackhat、不做笔画宽过滤。
  不需要压巡线：**巡线是开放曲线，没有孔**。
- **`_ring_quads(ink)`** —— 只取**最外层 + 真的有孔**的轮廓，收成 4 角；
  `_drop_nested` 丢掉落在别人框里的（一张卡上有外框 + 内部图形两圈环）。

**关键决定：ring 候选跳过 `_refine_quad` 和 `_verify_quad`。** 理由：

- `_refine_quad` 把边滑到「框线」上 —— 但 ring 的框**就是那条环轮廓本身**，没有可滑的余地。
  实测在**被锯碎的二值图**上滑，会把好框推坏。
- `_verify_quad` 的闭合度是对着**同一张碎图**量的。实测它反而在拒好框：
  五3 四边命中 `[0.53 1.00 0.47 1.00]`、正5 `[1.00 0.93 1.00 0.47]`，两条边过不了 0.65 的底线，
  **而这两张卡单独 warp 出来判得完全正确**。

代价：**失去了闭合度那道假阳性防线**，见 §6.3。

## §2 停车距离

**`--card-trigger-dist-cm`（默认 43）是「停多远」的唯一旋钮**，经
`trigger_frac_at_dist()` 换算成框质心该压到画面的哪个高度。

| 真实距离 | 画面比例 |
|---|---|
| 20cm | 0.728 |
| 25cm | 0.637 |
| 30cm | 0.559 |
| 35cm | 0.491 |
| **43cm（默认）** | **0.400** |
| 50cm | 0.334 |
| 60cm | 0.256 |

**默认 43 = 原来的 `--card-trigger-frac 0.4`，行为完全不变**（0.4 实算 0.4005）。
改这个数就能让车停近：35→0.491、30→0.559、25→0.637。卡片完全在画面里能撑到约 **16cm**。

**踩过的坑**：`trigger_dist_cm`/`trigger_y`/`trigger_box_w` 在
`ShapeDetector.__init__` 里**算出来了但从来没接进判决**（唯一读它的是一份打印脚本）。
所以代码里长期有**两个对不上的常数**：0.4 实算是 43cm，按 `trigger_dist_cm=40` 算出来是
0.432，而注释里写着 39.6cm。`--card-trigger-frac` 现在没有默认值，只留给测试用假 cy 驱动。

## §6 未解决 / 待验证（按优先级）

### 6.1 ⭐ `err` 与 `ang` 打架 → 跑出赛道

**现象**：直线段之后的左弯里，车不拐弯，直接往外滑。

**日志里的分界线非常干净**（2026-09-29 的实车日志）：

```
                    err     conf    ang     curve    far    lr  lock  pair
第16行  ...       +20.4    0.86   +41.3   1/-20   -54    11   0   1.00
第17行 ←分界       +5.7    0.39   +20.2   0/-8     -9    11   0   0.00
```

**两个字段同时塌：`pair` 1.00 → 0.00，`conf` 0.86 → 0.39。**
`pair` 是 `bottom_pair_ratio`（底部锁定 y=350-399，z≈20-27cm 的配对率）。
**而 `lr=11` 全程不变** —— 近带两条边线**都还看得见**，坏的是**底部锁定**，不是波段扫描。

**然后 `err` 和 `ang` 开始互相矛盾**：

```
err = -17.1cm   →  车道中心在右  →  右转 (wz = -0.250)
ang = +78.8     →  前方车线向左  →  左转
```

车按 `err` 走了右转。同一段里 `far` 在 `-9 → -48 → +33 → -23 → +67 → +83 → -6` 之间乱翻。

**理论分析**（这条是推断，等帧来验证）：

> `ang` 和 `err` **不是同一类测量**，不能平等融合。
>
> | | 类型 | 错了会怎样 |
> |---|---|---|
> | `ang`（航向） | **连续量** —— 看到线就有方向 | 错得**温柔**，只是噪声 |
> | `err`（横向） | **离散量** —— 依赖"**我在跟哪条线**"这个判断 | 判断一错，误差**整条车道宽地跳** |
>
> **数据支持**：`err` 从 `+20.4` 跳到 `-17.1`，摆幅 **37.5cm**；而车道宽是 **35cm**。
> 这个量级是「**中心被可见线镜像过去了**」的签名。而 `ang` 全程 `+60°…+79°`，**一次没翻**。

**理论上的正确解法**：`bottom_pair_ratio` 就是「我知道自己在跟哪条线」的**证据量**，
应该拿它当**横向项的门控权重**，而不是二元前提：

| `pair` | 中心是 | 横向项该有的权重 |
|---|---|---|
| 高 | **实测** | 全额 |
| 0 | **推断**（不确定度≈一个车道宽） | **坍缩到近 0，让航向项接管** |

这就是按测量方差反比加权。**现有机制为什么没接住**：

1. `confidence_weighted_ema` 按 conf 降权，但故障段 conf 是 0.29~0.53，**不是 0**
2. 更根本：**`conf` 把「像素少」和「看错线了」混为一谈**。锁定率才是关于歧义的专用证据，
   而它**根本没进融合**
3. `--single-line-gain` 只在「单线」时生效，而 `lr=11` 说明**两条线都看得见** —— 
   **两个保护都没触发**

### 6.2 `--dump-on-loss` 已加，**还没拿到数据**

每帧存两个 jpg（原图 + 检测器自己的叠加图，**叠加图能看到它以为在跟哪条线**）+ 一个 json。

### 7.0 ⚠️ 我下过的错结论（本节存在的主要理由）

| 我说过 | 实际 | 推翻它的证据 |
|---|---|---|
| **"6card 不是这台相机拍的，相机模型失配"** | **完全错**。6card 就是实车拍的，相机模型没问题 | ① `camera_config.py` 里本来就有 `_pose_verified` 字段（2026-09-22）记录模型是拿这类图验过的（"图卡平放地面、机器人正对拍摄，按 h=32.5 反推边长 9.68~10.09cm"）② `_square_on_ground` 在 31 张里过 21 张 ③ (pitch, vfov, 主点偏移) 联合拟合**不收敛**，最优点物理上荒谬（pitch 56°、vfov 38°、h=61.6cm）④ 失败卡与通过卡在尺寸、画面位置上分布完全相同 |
| "找框坏在候选生成" | 错。候选是好的 | 两道后置验证一放开，框 31/31 |
| "`area_max` 是元凶" | 它确实错了（差 10 倍），但**错得不够以致命** | 真正致命的是它后面两道验证 |
| "`hu` 每一处都对" | 退化，不能用作旁证 | 实车每一帧每张卡都读 `hu=circle`，距离 0.005~0.07，**比模板间最小间隔还小** |

**教训（写给下一个 agent）**：怀疑"数据和模型不匹配"时，**先 grep `*_verified` 之类的
验证记录字段**，再拟合一遍（真失配会在正确参数处收敛出尖锐最小值），再找对照组。
三条任一没做，就别说"不匹配"。
