# Orin Nano 板子部署与检测命令

从空白板子到跑起来。按顺序执行，别跳步。

## 1. 性能拉满 ⚠️ 必须在测任何性能数据之前

```bash
sudo nvpmodel -p --verbose      # 先看有哪些档
sudo nvpmodel -m 0              # 最大性能档
sudo jetson_clocks              # 锁最高频
```

Orin Nano 默认跑低功耗档。不开这个直接测帧率，数字偏低，会误判成「必须编译 OpenCV」。

## 2. 基础工具

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip v4l-utils git
```

## 3. 代码 + 权重

代码从开发机推过去（GitHub 443 在国内常超时）：

```bash
# 在开发机上执行（同一局域网）
scp -r jetson/ <user>@<板子IP>:~/Robocup/
```

**别漏 `jetson/shape_cnn_best_v2.pt`** —— 缺了图卡识别会静默退回规则法兜底。

## 4. Python 环境

```bash
python3 -m venv ~/robocup-venv
source ~/robocup-venv/bin/activate
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
pip install "numpy<=1.26.4"
pip install pyserial
pip install torch==2.12.0+cu132 --index-url https://download.pytorch.org/whl/cu132
```

`numpy<=1.26.4` 是硬约束 —— torch 的 cu132 wheel 与 numpy 2.x 冲突。

## 5. 探测 ← 分水岭

```bash
cd ~/Robocup/jetson/gpu_vision
python probe.py
```

看三样：OpenCV 版本、`cv2.cuda` 设备数、每算子 CPU 耗时。

JetPack 7.2 预装的 OpenCV 4.8.0 不带 CUDA，设备数大概率是 **0** —— 这是正常的，
程序会自动走 CPU 回退，功能不受影响，只是慢一些。

## 6. 相机

```bash
ls /dev/video*
v4l2-ctl --list-formats-ext -d /dev/video0
```

记下支持的分辨率档位和输出格式（MJPEG / YUYV）—— 决定将来有没有硬解可用。

## 7. 串口权限

```bash
sudo usermod -aG dialout $USER
```

**要重新登录才生效。**

## 8. 跑起来 + 测帧率

```bash
# 纯视觉（不开串口），测全链帧率
python run_robot.py --headless --no-serial

# 接串口实车
python run_robot.py --headless

# 限时跑，30 秒自动停（环境变量名是 REAL_CAR_MAX_SEC）
REAL_CAR_MAX_SEC=30 python run_robot.py --headless --no-serial

# 相机不是 0 号时
python run_robot.py --headless --no-serial --cam 1
```

打印第一项就是 `fps=`，跑 20~30 秒取稳定值。

## 9. 判据

| 全链 FPS | 动作 |
|---|---|
| ≥ 15 | **够了，收工**。控制环只有 10Hz |
| 10–15 | 降分辨率：加 `--width-640`（代价：红条测距精度减半） |
| < 10 | 上面那条 + 考虑编译带 CUDA 的 OpenCV（见 README，CUDA 13.2 上需 cudev 补丁） |

## 10. 编译后验收（仅编译了 OpenCV 才需要）

```bash
python compare_cpu_gpu.py
```

GPU 与 CPU 逐算子等价性必须 PASS，否则说明编译出的算子行为不一致。
